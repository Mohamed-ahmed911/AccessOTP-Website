THE CHALLENGE

Security shouldn't depend on reading a code.

Traditional OTP journeys can introduce extra steps for people using assistive technology.

SMS-dependent steps

Moving between a banking app and a message can interrupt the sign-in flow.

Manual entry

Locating, remembering and entering a short-lived code can be difficult for some users.

Accessibility gaps

Authentication works best when accessibility is considered from the beginning.

HOW THE CONCEPT WORKS

One flow. Fewer barriers.

The Android project implements two apps on the same device: a bank demo and an Authenticator. Our interactive website presents a visual simulation of that workflow; real bank integration would require formal permission and independent security review.

See the simulation
  1. 01

    Username and four-digit PIN

    The user provides a demo username and four-digit PIN in the Android bank application.

  2. 02

    Same-device verification request

    The bank demo sends a protected verification request to the installed Authenticator app.

  3. 03

    Automatic completion

    The Android demo bank checks the returned verification proof and completes sign-in without manual OTP entry. The website recreates this visually only.

IMPLEMENTED ANDROID FEATURES

More than automatic verification

Explore the app features shown in our Android prototype and the browser simulation.

Count & Morse vibration

Choose Count or Morse tactile PIN feedback (or Off for visible entry). Hidden PIN entry requires vibration and cannot be used while vibration is Off.

PIN limits & protected verification

The Android bank temporarily locks sign-in for 60 seconds after five wrong PIN attempts. Companion verification uses signature-protected communication and Android Keystore.

Private PIN & demo banking

Hide PIN keypad digits, then explore a fictional balance hidden by default, Feel balance vibration, simulated transfers and transaction history after sign-in.
