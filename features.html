PROTOTYPE CAPABILITIES

Features built around the user

The demo currently simulates verification; these concepts describe the intended product direction, not a deployed banking security system.

No manual OTP input

The simulated bank completes verification without displaying an SMS code or asking the user to type one.

Demonstrated in prototype

Bank-authorized workflow

Designed around a future formal integration between a participating bank and AccessOTP, rather than bypassing app security.

Future integration requirement

Accessible interaction patterns

Clear wording, labeled controls, keyboard navigation, and screen-reader status updates in the web demonstration.

Implemented in website demo

Security-conscious concept

A real product would require user consent, bank-side authorization, authenticated communication, logging, and independent security testing.

Design principle
TECHNICAL APPROACH

How it is modeled

A front-end prototype illustrates a request → verification → response journey. No live bank API, SMS interception, or real account authentication is present.

TARGET AUDIENCE

Who it's for

People who are blind or have low vision, particularly those who find conventional OTP flows cumbersome or inaccessible.

DIFFERENTIATION

What we prioritize

Accessibility at the center of the verification journey rather than treating assistive access as an afterthought. This is our product positioning, not a validated market comparison.
